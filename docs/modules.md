# Tidy Base Info modules

What each file in `Scripts\` and `tools\` does, in detail.

| Path | Holds |
|---|---|
| `Scripts/main.lua` | Entry point: wires config, logger and grid; registers the canvas observer (`NotifyOnNewObject` on `PalUIInsideBaseCampCanvas`), the `Set Pal Slots` hook (fires post-body on Blueprint paths; the roster source), and the scroll and inspect keybinds under the player's chosen modifier (an empty key name turns that bind off, a mouse-button name is refused, an unknown modifier warns and falls back to Alt). A settings change re-runs `refreshKeybinds`: UE4SS cannot unregister a keybind, so the new combination is registered and every older registration turns inert by checking that the settings still name its own combination. It also starts `livecfg.start` with the callback that re-reads the keybinds and calls `grid.applyConfig()`. |
| `Scripts/grid.lua` | The panel surgery: lazily builds SizeBox -> ScrollBox -> WrapBox in `CanvasPanel_WorkerInfo` on first roster delivery, hides the five vanilla rows and the `+N` counter (original visibility captured once, re-collapsed by a maintenance loop because the game re-shows them), renders one trimmed vanilla row per pal as a SizeBox -> Button -> row cell (skipped when the roster signature is unchanged), drives the hover and pin detail row (a second created instance of the same vanilla row widget, unbound before each rebind), handles click-to-open-details (HUD-service dispatch with pin fallback, press-edge polled on a fast click loop), the right-click context menu (ids `palbox`/`resummon`/`assign`, labelled through `I18n.t` at build time; server-request RPCs plus the HUD dispatch recipe), owns the cursor state machine (hold with hover-escalated full blocking, persistent toggle), and the fail-soft `disable()`/`restoreVanilla()` path, which also fires when a non-empty roster yields zero icons. |
| `Scripts/config.lua` | Every player setting, 32 flat scalars, each under a comment block of one player-facing sentence plus a `Range low to high` line or an `Options:` list: grid bound, size, placement and cell geometry, portrait scales, `showEmptySlots`, hover-row placement, `keybindModifier` and the scroll/inspect/hold keys, `cursorGraceTicks`, `suspendInputOverPanel`, `openDetailsOnClick`, the action menu's width, placement, `menuItemPaddingX`/`Y` and `menuItemGap`, `resummonTimeoutMs`, `maintenanceMs`, `liveReloadSeconds`, and `language`. |
| `Scripts/livecfg.lua` | The settings watcher: `LoopAsync` re-reads `config.lua` every `liveReloadSeconds`, and only on changed text parses it with `load(text, "@config.lua", "t", {})` in an empty environment, requiring a returned table. A good parse is merged into the live settings table in place (a dropped setting returns to its boot value, a setting whose type changed keeps the value in force), logged as one line, and handed to the apply callback. The loop body does file IO and plain Lua only; the single `ExecuteInGameThread` per applied edit is the rare user-triggered shape the LoopAsync ban carves out. An unreadable, half-written or non-table file warns once and leaves the last good settings in force. |
| `Scripts/i18n.lua`, `Scripts/palette.lua`, `Scripts/logger.lua` | `I18n.t(key)` in the game's language (`Assets/lang/en.ini` first, the reported language overlaid, `I18n.fallback` in English when no file can be read at all); the palette declaration; and the `[TidyBaseInfo]`-prefixed log helpers. |
| `tools/test/run_tests.lua` | Offline suite for the parts that need no game: the language files and their loader, the palette, `config.lua`'s contract (every setting scalar, read by the code, and carrying a comment; every documented choice list contains its own value), and the settings watcher driven by hand over a real file (changed, unchanged, half-written, non-table, wrong value type, dropped setting, interval clamped and turned off). |
| `tools/lang/` | `ui.tsv` (English), `translations/<code>.tsv` and `build_lang.py`, which refuses a build whose `i18n.lua` fallback table disagrees with `ui.tsv`. |
